# note Workspace｜ROGNALIA 使い方ガイド

日々のメモ、執筆方針、記事、画像、公開後の振り返りを、自分専用の作業場所に残しながらnoteを続けられます。ここでは、AIとの一つひとつの会話を「タスク」と呼びます。

## はじめに

PCのフォルダを読み書きできるCodex DesktopやChatGPT Workでnote Workspaceプラグインを選び、[READMEの開始文](README.md#はじめ方)を送ってください。必要な機能は[対応環境と機能](docs/platform-capabilities.md)で確認できます。

まず一記事を仕上げたい場合は、[note Studio mini｜ROGNALIA](https://chatgpt.com/plugins/plugins_6a8ae5578dd08191aff6730618697465)も選べます。

## セットアップ

現在のnote運用、目的、テーマ、読者、文体、投稿頻度、材料の残し方、使いたい機能について質問します。決まっていないことは、一緒に考えながら進められます。

AIが回答を運用案にまとめます。内容、PC内の保存先、作成するタスクを確認すると、専用の作業場所が整います。定期実行を希望する場合は、対象と曜日・時刻も確認します。

メモや記事は選んだフォルダに保存されます。AIへ渡す資料には、利用中のAIサービスで処理してよいものを選んでください。保存場所とAI処理の関係は[データの保存先と形式](docs/storage-and-data-model.md)を参照してください。

## 普段の入口

セットアップ後は、そのまま用意されたタスクを使えます。別の会話から再開する時は、同じプラグインを選び、保存済みのnote Workspaceのフォルダを指定してください。初回の質問へ答え直す必要はありません。

日々の出来事や気持ちを残す時は `📔 note｜日記・体験ログ`、記事を書く時は `✍️ note｜記事制作` へ話しかけてください。使い方に迷った時は記事制作担当へ相談できます。

| やりたいこと | 話しかける場所 |
|---|---|
| 今日あったことを話す、質問してもらう、メモを残す | `📔 note｜日記・体験ログ` |
| 記事を書く、下書きを整える | `✍️ note｜記事制作` |
| 次のテーマや今週の方針を考える | `🧭 note｜戦略・編集方針` |
| 公開後の数字を確認する | `📊 note｜計測・公開ログ` |
| 画像を直接調整する | `🎨 note｜画像制作` |

セットアップに使ったタスクが戦略担当になり、計測・記事制作・画像制作・日記のタスクが加わります。設定やメモは共通の保存先から引き継がれるので、担当間でコピーする必要はありません。

## 日記・体験ログを残す

日記担当には、今日あったことや、まだまとまっていない気持ちをそのまま話せます。記事を書く予定がなくても使えます。

```text
今日あったことを聞いて。
```

話題に迷ったら、質問から始められます。

```text
何か質問して。
```

会話は日時と話者を分けて、選んだPCのフォルダへ原文で保存します。残したくない話は「保存しないで」と伝えてください。会話自体は利用中のAIサービスで処理されるため、そこで扱ってよい情報を話してください。

テーマを考える時や記事を書く時は、関係する記録を参照できます。日記を保存することと、記事に使うことは別です。記事に使う時には公開できる範囲を確認します。

以前の4タスク構成を使っている場合は、今の担当に日記担当の追加を相談できます。保存済みの記録は引き継げます。

## 記事を書く

書きたいことやメモを、記事制作担当へ送ってください。

```text
今日はこの出来事を書きたい。
```

必要な調査と短い質問を経て、構成とトーンを確認します。その後、本文、タイトル候補、タグ、X投稿文を仕上げます。タイトルを選ぶと見出し画像の制作へ進み、記事と画像をまとめて受け取れます。差し絵は希望する場合に追加できます。

画像だけを調整したい時は画像制作担当へ話しかけられます。通常の記事制作では、原稿を画像担当へ運ぶ必要はありません。

## 次に書くことを考える

戦略担当では、次の記事候補、目的や読者、投稿頻度、休止、文体の好みを相談できます。

```text
次は何を書こう？ 手元のメモから候補を考えたい。
```

候補は、本人の目的、一次情報、過去記事、参考指標から考えます。予定にないテーマも、記事制作担当へそのまま伝えられます。

## 公開後を振り返る

計測担当では、公開日・記事URLと、ダッシュボードのインプレッション、ページビュー、スキ、コメント、売上を記録します。対象期間と、記事別・アカウント全体のどちらかを揃えて比較します。取得できなかった値は `0` にせず、取得状態を残します。

```text
今週の公開記事と数字を記録して。
```

定期実行を設定すると、計測と翌週の記事候補の更新を任せられます。セットアップ完了時に、利用中のアプリから設定済みの対象と次回実行時刻を案内します。PC内のファイルを使う定期実行には、実行時にPCとアプリが動いている必要があります。

予定や現在状態を確かめたい時は、普段のタスクへ聞いてください。状態を確認できない場合は「未確認」と案内します。

## 1つのタスクで使う

複数のタスクを使いたくない場合は、`📝 note｜執筆サポーター` 一つへまとめられます。日記、企画、計測、記事、画像の相談を同じ会話で進め、保存方法と下書き登録前の確認は標準運用と共通です。

セットアップ時に選べます。後から切り替えたい場合も、普段のタスクへ伝えてください。

```text
担当を、一つの執筆サポーターにまとめたい。
```

## noteへ下書きを登録する

ブラウザ操作を使える環境では、完成した記事・画像・リンクを確認した後、その記事の新規下書き登録を依頼できます。保存して閉じ、非公開の下書きとして確認できたら登録結果を受け取れます。

記事の公開・予約投稿と、既存記事・既存下書きの上書きは行いません。下書き登録を使わない場合も、完成した本文と画像を受け取れます。

## 設定を変える

投稿頻度や休止は戦略担当で相談できます。テーマ、読者、公開範囲、保存先、担当の構成を変えたい時は、普段のタスクへ伝えてください。保存先変更では、移すデータとバックアップを確認してから進めます。

```text
投稿頻度を少し減らしたい。今の方針を見直して。
```

さらに自分の運用に合わせたい場合は、[カスタマイズと拡張](docs/extending.md)を参照してください。
