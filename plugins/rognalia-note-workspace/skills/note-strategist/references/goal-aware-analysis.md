# 目的別の参考指標分析

## 目的

同じ数字を全利用者へ同じ重みで当てはめず、利用者がnoteで実現したいことに合わせて、見る範囲と問いを小さく切り替える。指標は候補を採点するためではなく、次に確かめる問いを作るために使う。

この契約は2026年9月8日以降のブラウザ版noteダッシュボードを対象にする。旧`views`、スマートフォンアプリに残る旧表示、新しい`impressions`と`page_views`を相互変換または合算しない。

## 分析レンズを選ぶ

その回の利用者の依頼を最優先し、指定がなければ`profile/creator-profile.md`の「noteで達成したいこと」「半年後の成功」「優先する目標」「数字以外に残したいもの」と`strategy/strategy.md`を読む。新しい必須質問や設定項目は増やさない。

下表から主レンズを一つ、必要な時だけ副レンズを一つ選ぶ。複数に当てはまっても全項目を毎回集めない。どれを選ぶかで提案が大きく変わり、既存記録から決められない時だけ、利用者へ一問で優先を確認する。

| レンズ | 主に確かめること | 主に使う材料 | 単独では言わないこと |
|---|---|---|---|
| 継続・記録 | 無理なく残せているか、過去記事も期間内に読まれているか | 記事台帳、公開本数、本人の残した価値、関連する記事のPV | 反応が小さいので記録価値がない |
| 届き方 | note内で見つかる機会と、記事が開かれる量がどう動いたか | アカウントと記事のインプレッション・PV、アカウント単位の流入元 | PV÷インプレッションを厳密なCTRとする |
| 関係 | 期間中に明示的な反応や会話が生まれたか | スキ、コメント、必要な時だけ直近28日のフォロー表示 | スキ÷PVを満足率、コメント数を人数とする |
| 専門性・仕事 | 古い専門記事が継続して開かれ、外部発見の入口になっているか | 関連記事のPV、アカウント単位の検索・外部domain流入、本人が別に記録した相談 | domain流入を記事別流入、AI引用、相談、契約とする |
| 収益 | 選択期間の販売活動がどう動いたか | 売上、必要な場合だけ記事・マガジン・メンバーシップの区分、本人の販売記録 | 売上を受取額、利益、記事だけの効果とする |

## 比較の最小手順

1. 今回の主レンズと、答えたい問いを一つ決める。
2. 増減を見る時は、原則として当日を含まない同じ長さの完了期間を二つ選ぶ。開始日、終了日、画面の集計時刻を残す。
3. 届き方、専門性、仕事を見る時は必要に応じてアカウント観測を一件取り、関連する記事だけ記事観測を取る。全記事、全panel、売上を毎回必須にしない。
4. 「画面で確認したこと」「そこから考えられること」「まだ別の証拠が必要なこと」を分ける。
5. 結論は最大三点、次に試す行動は原則一つに絞る。大きな方針変更ではなく、次の同条件比較で確かめられる提案にする。

当日を含む観測も現況確認には使えるが、完了期間との増減判定にはそのまま使わない。公開直後の記事同士を比べる時は、公開からの経過日数も揃える。期間内の一覧には期間前に公開した記事も含まれるため、「期間内に公開した記事の成績」と読み替えない。

## 指標の意味と境界

- `impressions`: note内の一覧、検索、ハッシュタグ、クリエイターページ、関連記事等で記事が表示された回数。人数や記事を開いた回数ではなく、本人への表示も含む。
- `page_views`: 記事ページが開かれた回数。人数、読了、見込み客ではなく、本人の閲覧も含む。
- `likes`と`comments`: 選択期間中に新たに付いた件数。公開ページ上の現在累計とは分ける。スキは記事を開かずに付く場合があり、コメントには本人の返信等も入り得る。
- `sales`: 選択期間の有料記事、マガジン、メンバーシップ、チップ等の売上。受取額ではなく、返金が反映されない場合がある。
- 流入元: アカウント全体のPV分類。通常ダッシュボードの値を記事別へ推測配分しない。流入元合計と上段PVは集計方法により一致しない場合がある。

`note.com`はnote内の経路を示すが、ホームや検索等の細分までは示さない。`no referrer`をすべて直接訪問または固定読者としない。Google、X、`chatgpt.com`等の表示名は流入分類であり、掲載順位、検索需要、AI回答内の引用、事業成果を証明しない。

直近1か月のまとめは独立した直近28日の可変カードであり、選択期間と連動する完全な台帳にしない。フォロー表示は公式に純増と確認できない限り、解除を差し引いた純増と呼ばない。note Proのアナリティクスは通常ダッシュボードと別機能なので、利用可能と仮定しない。

## 計算してよいこと、名前を変えてはいけないこと

同じ定義、同じscope、同じ長さの完了期間なら、各指標の差や増減率を計算できる。分母が正確な0、未取得、旧指標、期間不一致の場合は率を出さない。

`page_views / impressions`は参考比率として計算できても、外部流入を含むPVとnote内表示の分母が一対一対応しないため「クリック率」と呼ばない。`likes / page_views`も「PVあたりのスキ件数」にとどめ、「満足率」「読了率」と呼ばない。記事、検索、相談、契約、売上は別段階として扱い、合成スコアへまとめない。

## 取得不能と旧履歴

`available`の正確な0だけを0として扱う。取得手段がない`unavailable`、画面にない`not_visible`、取得に失敗した`fetch_failed`、scope上の対象外である`not_applicable`、今回の目的では収集しなかった`not_collected`はすべて`value: null`のまま扱う。

schema version 1の`views`は当時の意味のまま残す。schema version 2へ変換せず、v2の5指標や流入元との連続推移を作らない。移行後の基準線が必要なら、新しい画面で同じ完了期間をv2として新規観測する。
