# 記事制作契約

## 1. 方向の優先順位

記事の方向は次の順で決める。

1. 今回の利用者の明示指定。
2. 利用者が選んだ既存下書き。
3. 最新の週間recordにある一候補。利用者確定の`user_selection`と、未確定の`strategy_recommendation`を区別して示す。

週間計画は標準の候補であり、今回の利用者指定を上書きしない。推奨候補から書く場合も、記事metadataへ週、計画path、revision、revision hash、record type、利用者確定の有無、candidate IDを残し、実在する同じrevisionと候補へ照合する。候補IDだけを出所の証拠にしない。計画外テーマを理由に再計画を強制せず、その一記事を進める。別テーマが出た時は、一つの記事へ混ぜず次の候補として分ける。

## 2. 調査

### 調査する場合

- 現在の制度、価格、製品仕様、人物、企業、統計、出来事を扱う。
- 読者の判断に外部事実が必要である。
- 既存記事との重複や位置づけを確認する必要がある。
- 利用者が調査を求めた。

調査は本人への質問より先に行い、公開sourceを実際に読む。検索結果の見出しや抜粋だけを確認済み事実にしない。現在性が重要なsourceは取得日を残す。

### 調査しない場合

- 本人の記録や随筆だけで記事の目的を満たせる。
- 外部情報を加えると本人の話が薄くなる。
- 利用者が提供した資料の整理だけを依頼している。

調査しない判断は`not_needed`として記事metadataへ残せる。Webを使えない時は`unavailable`とし、調査済みと装わず、現在情報の断定を避ける。

## 3. 最大3問の取材

質問は本人にしか答えられず、記事の中心を具体化するものに限る。

- 実際に起きた場面。
- その時に見た変化や反応。
- 選んだ行動と判断理由。
- 前後で変わった考え。
- 本人の正確な言葉が必要な箇所。

一記事の合計を最大3問とする。一度に三つ聞く必要はない。回答によって次の質問が不要になれば止める。既存下書き、文脈パック、直前の会話に答えがある質問は数を使わない。

回答を記録する場合も、本人の原文を勝手に教訓へ変えない。本文へ使う材料は、公開可能またはその記事での使用確認済みにする。

## 4. 文脈パック

執筆へ渡す最終文脈パックは、その記事に使う材料を揃えた後に作る。含めるのは関係する最新の一次情報カードだけとし、生ログ全体を渡さない。

- 「記事へ使用できる材料」は本文、タイトル、タグ、告知文に使える。
- 「公開前確認が必要な材料」は、確認が取れるまで断定利用しない。
- 「記事へ使用しない背景」は、本文、タイトル、タグ、告知文へ移さない。
- 「まだ足りない情報」が記事成立を妨げる場合は、最大3問の範囲で確認する。

文脈パックは上書きしない。すでに作成済みで、追加回答を含む新しい材料が不可欠になった場合は、既存packを黙って書き換えず、材料を揃えてから新しい記事IDで作り直すか、今ある材料だけで成立する方向へ狭める。

## 5. 構成とトーンのgate

本文を書く前に、次が利用者の意図として確定している必要がある。

- 記事の中心となる一文。
- 想定読者と読後に残したいもの。
- 導入、主要な展開、終わり方。
- 読者との距離、温度、長さ、ユーモア等のトーン。

「この構成とトーンで本文を書いてよいか」が分かる形で提示する。利用者がすでに具体的に指定した要素は再確認しない。承認前に本文を完成させない。

## 6. 本文と一次性

本人の場面、観察、言葉、判断が記事の進行を作る。外部情報は本人の話を支える範囲に置き、一般論を主役にしない。

- 経験は本人の経験として書く。
- 公開情報はsourceで確認できる射程だけを書く。
- 推測は推測として書く。
- 元材料にない感情、成果、数字、引用を作らない。
- 同じ主張を言い換えて水増ししない。
- 本人の正確な言葉を整える時は意味を変えない。

原稿返却前の一次性と文体は`note-draft-quality`を正本にする。品質結果は利用者へ表示しない。

## 7. 記事一式

通常は次の順で返す。

1. タイトル3案。
2. 本文。
3. noteタグ5〜6個。
4. X投稿文。

タイトルは本文で扱っていない約束、煽り、数字を追加しない。noteタグは記事の話題と読者が探す言葉を混ぜ、無関係な人気語を入れない。X投稿文は記事の内容を短く伝え、本文にない成果を約束しない。

本文に見出しを使う場合は、行頭へ`[大見出し]`または`[小見出し]`を付けて種別を明示する。後続の下書き登録では識別子を本文へ貼らず、見出し書式へ変換する。見出しがない記事も有効であり、構成案の項目数に合わせて見出しを機械的に増やさない。

本文だけを求められた場合は、本文だけを返す。品質結果、調査ログ、修正一覧、内部Skill名、工程移行の報告は記事一式へ混ぜない。

## 8. 次工程の境界

タイトル選択後に、確定タイトル、中心場面、読者、トーン、必要な短いコピー、画像要件だけを画像工程へ渡す。記事全文や長い会話履歴を渡さない。

記事一式の完成とlocal保存は、画像生成、note下書き登録、公開を承認しない。note操作の確認は画像を含む完成物が揃った後に別工程で行う。
