# noteエディター操作

## 操作の原則

- 承認済みregistration packageと、その時点で操作可能なbrowser面を一つ使う。
- 現在の画面で見えるlabel、役割、状態を確認し、固定座標や古いselectorだけに依存しない。
- 最初の文字入力前に承認packageのvalidatorと開始記録を完了する。
- noteは入力中にも自動保存され得るため、文字入力以降を外部書き込みとして扱う。
- OGP等の見た目より、承認済み本文、URL、画像、保存状態を優先する。

## ログイン状態

noteを開いた直後の一回だけで未ログインと決めない。主要要素の描画を待ち、初回で判断できなければ画面状態を再取得する。

現在のUIで利用中と判断できるprofile、通知、新規投稿導線等を確認する。再確認後も明示的なログイン画面で、認証済み要素がない時だけ、利用者へ画面上での手動ログインを依頼して停止する。ID、password、認証codeを会話へ送らせない。

ログイン完了は承認内容の変更ではない。packageのhashが変わっていなければ再承認せず続ける。

## 新規記事

noteの新規テキスト記事を選び、空の新規editorであることを画面上で確認する。既存記事のタイトルや本文が表示されていたら入力しない。

開始記録がすでにあり保存結果がない時は、先に同じ下書きの途中保存を探す。対象を確実に特定できない場合は、新規記事をもう一件作らない。

## 本文と見出し

確定タイトルを入力する。記事draftから`[大見出し]`と`[小見出し]`の識別子だけを除き、見出し名を独立段落として本文末尾のnoteタグ行まで入力する。

識別子があった段落へ、現在表示される大見出しまたは小見出しの書式を一つずつ適用する。次の段落まで見出しになっていないか確認する。目次、区切り線、中央寄せ、引用、太字は、承認packageにない限り足さない。

## 本文末尾のnoteタグ

packageが参照するdraft末尾には、最終段落から一行空けて、`#`付きnoteタグ5個または6個が半角空白区切りの一行で含まれる。この行を追加生成、分離、並べ替え、言い換えず、本文の一部としてそのまま入力する。

タグ登録を確認するために公開設定画面へ進まず、本文末尾からタグを削除しない。

## URL

本文内の独立URL行はURL末尾で改行し、OGP表示を試せる。追加URLはpackageにURLと挿入位置がある時だけ、その位置へ登録する。

OGPが出なくても正しいURLがlinkとして残れば続行する。結果記録では`ogp`または`link`を区別する。URLが消えた、別URLになった、linkとして機能しない場合は入力を止める。

## 見出し画像と差し絵

見出し画像は記事先頭の見出し画像設定から登録する。本文内の画像挿入へ誤って入れない。表示範囲の確認がある場合は、主役や文字が切れていないことを確認する。

差し絵はpackageにある指定段落の直後へ一枚だけ挿入し、指定ALTとcaptionをそのまま設定する。画像、位置、upload完了を確認できない時は登録済みとしない。

## 保存して閉じる

現在のUIで確認できる保存完了の根拠を一つ以上得る。明示的な下書き保存がある場合は使い、公開に進む操作は使わない。

保存後にeditorを閉じ、公開前の下書き表示または下書き一覧で非公開状態を確認する。下書きURLを取得し、公開URLと呼ばない。

## UI変更時

目的の操作や保存状態を特定できない時は、近いbuttonを推測で押さない。確認できた最後の状態で止める。開始記録後なら、新しい下書きを作らず同じ対象の照合を次の一手にする。
