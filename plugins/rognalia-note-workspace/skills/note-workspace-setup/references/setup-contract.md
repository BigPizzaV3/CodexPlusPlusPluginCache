# セットアップ契約

## 目的

利用者が承認前に、何が作られ、何が外部状態へ影響し、何がまだ保留されるかを一度で判断できる提案を作る。

## 開始時の期待値

最初の質問より前に、セットアップの負担と完成後の状態を短く説明する。次の意味を含めるが、定型文を長く読み上げる必要はない。

```text
note Workspaceは、今後の記事づくりを支える自分専用の編集部を作ります。
最初だけ、目的やテーマ、文体、続け方、保存先を数回に分けて伺います。
基本的には質問へ答え、最後の提案を確認するだけです。承認後の作成と担当の準備はこちらで進めます。
一記事をすぐ作れれば十分なら、note Studio miniも選べます。
```

利用者がWorkspaceを選んだ後は、質問が多いことへの自己弁護を続けず、関連する一まとまりだけを聞く。既に会話や既存workspaceから分かる項目は省く。

5タスク標準では日々の話は日記担当へ、記事を書く時は記事制作へ話しかける。担当間の情報コピーは不要と説明する。簡易は日記を含む5役が一つの会話へ集まる。品質と承認境界は変わらず、後から変更できる。

## 提案の形式

利用者向けには、内部schema名や実装用語を見せず、次の順で簡潔に示す。

```text
現在地
- 既存のnote運用:
- miniの利用:
- 引き継ぐ材料:
- 止まりやすい工程:

noteで目指すこと
- 最優先:
- 半年後の成功:
- 数字以外に残したいもの:

読者とテーマ
- 読んでほしい人:
- 中心テーマ:
- 避けるテーマ:
- 公開できる範囲:

続け方
- 希望頻度:
- 最低限の頻度:
- 使える時間:
- 一次情報の残し方:

役割
- 運用方法: 5タスク標準 / 1タスク簡易
- 🧭 note｜戦略・編集方針:
- 📊 note｜計測・公開ログ:
- ✍️ note｜記事制作:
- 🎨 note｜画像制作:
- 📔 note｜日記・体験ログ（この担当の会話を話者別に保存。保存しない話は指定可能。記事使用は別確認）:
- 📝 note｜執筆サポーター（1タスク簡易の場合）:
- 各タスクが最初に返す案内:

保存先
- workspace:
- 主なfile:

任意機能
- note新規下書き登録:
- 計測:
- 週間企画:
- 計測の定期実行（曜日・時刻・対象task）:
- 週間戦略の定期実行（曜日・時刻・対象task）:
- クラウド同期:

最初の一週間
1.
2.
3.

今回作るもの
-

まだ作らないもの
-
```

ヒアリング途中では、この全形式を毎回表示しない。変わった項目と、次に決める一まとまりだけを短く返す。全体提案は、書き込み対象を承認してもらう段階で一度表示する。

空欄を埋めるために推測しない。未定の項目は「まだ決めていません」と示し、実装に必要な項目だけ追加確認する。

## 承認として扱える回答

提案全体または特定項目を指して、利用者が作成、保存、設定を明示した回答だけを承認として扱う。

- 「この内容で作って」「workspaceだけ作って」は対象が明確なら承認になる。
- テーマ、頻度、保存先への回答だけでは作成承認にならない。
- 「定期実行はあとで」「クラウドは使わない」は、その項目を保留または無効にする指定である。
- path、作成file、タスク名、外部操作が承認後に変わった場合は、変わった対象だけ再確認する。

## setup configへの対応

承認済み内容を[`schemas/setup-config.schema.json`](schemas/setup-config.schema.json)へ変換する。

- `profile`には、利用者が確認した目的、テーマ、読者、公開範囲、継続条件、文章と画像の希望だけを入れる。
- `operation`には、locale、timezone、下書き登録、計測、週間企画、定期実行の希望、local保存を入れる。
- `operation.task_mode`の新規標準・省略時は`standard_five`。希望時は`compact_single`を使う。`standard_four`は従来環境との互換用であり、新規の標準提案には使わない。
- 定期実行を希望する場合は、希望の有無だけでなく人が読める曜日と時刻を`schedule`へ入れる。計測をtracker、週間戦略をstrategyへ割り当て、計測を先にする。
- `task_names`は利用者が標準名を変更した場合だけ指定する。
- password、Cookie、API key、認証code、private URLを入れない。
- configは利用者所有の場所または一時領域で扱い、source repositoryへ保存しない。

## 書き込み単位

local workspace作成、タスク作成、定期実行、クラウド同期は別の書き込み単位である。一つの承認にまとめる場合も、提案内で各対象を列挙する。保留された単位は実行しない。

## 完了時の引き渡し

完了報告では、生成した`START_HERE.md`を利用者の構成に合わせて短く再掲する。標準5タスクなら日々の話と質問の依頼は日記担当、執筆は記事制作、方針は戦略へと示す。計測と画像は通常自分で開かなくてよく、情報コピーも不要と続ける。1タスク簡易運用なら、入口が一つで役割を選び分けなくてよいことを示す。

定期実行は、希望の記録、作成済み、次回実行確認済みを分ける。local workspaceの`automation_preferences`には希望だけを保存し、現在の作成状態は保存済み設定から推測しない。作成、変更、再実行、状態報告、重複判定の前にplatformから実際のautomation ID、対象task、schedule、次回実行を読み戻す。読み戻せない場合は`未確認`と報告し、作成済みとも未作成とも断定せず、重複作成しない。タスクを作れないhostでは、空のtaskが準備済みであるように見せず、開始指示の提示までであることを明記する。最後に、利用者の目的に合う最初の一言を一つだけ提案する。
