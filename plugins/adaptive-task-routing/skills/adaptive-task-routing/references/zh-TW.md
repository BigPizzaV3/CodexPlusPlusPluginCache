# Adaptive Task Routing：繁體中文參考

這是協調入口；Context 與模型決策仍由兩個子 Skill 負責。讀取 [共用政策](../../../shared/runtime-routing-policy.md)、[預設值](../../../shared/defaults.yaml) 與 [UX 契約](../../../shared/routing-ux.md)。相對路徑從目前文件所在目錄解析，共用資料在 Plugin 根目錄的 shared，不能當成 skills/shared。Gemini 已生成依賴附錄時直接使用內嵌契約，不啟動 sibling Skill 或另外讀外部檔案。

## 順序

1. 多步驟分析、稽核、規劃與執行可形成重要階段。只要求分析／計畫時先完成交付；要求執行時先提出可操作計畫，於修改前路由。簡短功能問題與無實質下一階段的完整回答不另造工作。
2. 先解析獨立 Context、Model 模式。一般對話可查詢或設定 ask／auto／off；未指定 Router 則同時設定兩者。模式變更本身不授權實作。
3. 將委派標記傳给 Context Router，載入其指令並取得實際對話、延續理由與交接成本。建議交接而使用者拒絕時，實際位置仍是目前對話。
4. 再委派 Model Router，提供已確認的 Context 與下一階段計畫。目的地或元件尚未確定時，明確標示未完成，不憑記憶合成結果。後續僅模型需求改變可重用已確定的 Context。
5. 依 UX 契約合併為一個 Routing 區塊：分隔線、品牌標題、動作、原因、對話去留建議、有用的 AI 設定與下一步。不要把行動優先誤解成把路由搬到使用者要求的分析之前。
6. `ask` 只在變更環境前或遇關鍵阻礙時詢問。retain 及不妨礙工作的 defer，直接繼續已授權工作；只要求計畫則結束交付，不開始實作。`auto` 仍需切換值得、已授權、可操作且可驗證。

## 顯示

使用 `### Adaptive Task Routing`，動作行嚴格依共用 UX 契約的繁體中文對照表，不使用「保留現況」等同義改寫；原因另起一段，以一至兩句說明。分析／計畫請求先完整交付內容，最後才放 Routing 區塊，不能以「以下為改善計畫」結尾。涉及後續實作時用「若後續進入實作」，不能暗示已獲授權。確認保留需要可靠的目前模型與原生推理設定、該階段品質及保留效益的依據；模型預設不能代替模型身分。模型未知的保留用暫時沿用，但不能覆蓋交接、指定目標或關鍵阻礙。

Context 啟用時，精簡版仍回答「是否需要開新對話」；沿用時說「對話：留在目前對話，不需開新對話。」；交接或全新開始時，合併說明建議動作與是否待確認，不另設是／否欄位。Context-off 與明確 Model-only 不顯示對話適合程度。原始 CURRENT／HANDOFF／CLEAN 只留在證據。

`recommended_setting` 外部稱「任務適配設定」，與「現在建議的動作」分開。確認保留時，compact 只顯示已觀察的目前 AI；暫時沿用可能來自目前設定未知或切換成本／效益不明。一般變更只詢問是否改用具名目標，不一併詢問是否重排計畫。預設 compact；要求詳細時顯示最低足夠設定、適配設定、升級理由。切換評分與探測資料不放一般輸出；詳細說明不等於內部推理。新對話不能假裝已建立，模型不能假裝已切換。

相同階段、環境與偏好未變時重用 Gate，不重複探測或新增活動日誌。每項宿主能力分開解析；未知 OpenAI 介面依模型 Router 的有界探測處理，不因使用者沒寫 CLI 就猜成 App。
