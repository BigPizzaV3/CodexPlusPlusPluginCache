# Adaptive Task Routing — 사용자 가이드

[English](README.md) · [繁體中文](README.zh-TW.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

**다음 행동과 설정을 유지해도 되는 때를 명확하게 보여줍니다.**

Adaptive Task Routing은 중요한 작업 단계가 바뀔 때 대화, 모델, 추론 설정을 평가합니다. 지금 할 행동을 먼저, 이유를 다음에 보여줍니다. 작업에 적합한 모델이라고 해서 진행 중에 바꿀 가치가 있는 것은 아닙니다.

작업 요구, 현재 설정의 적합성, 남은 작업량, 맥락의 연속성과 전환 비용을 고려합니다. 적절한 설정 유지도 유효한 결과입니다. 정보가 부족하면 임시 유지로 표시하고 적합성이 확인됐다고 주장하지 않습니다. 실제 비용 절감과 신뢰성 개선에는 검증이 필요합니다.

## 작동 방식

1. AI가 요청한 분석 결과나 실행 가능한 계획을 먼저 제시합니다.
2. 라우팅 안내는 유지, 임시 유지, 새 대화, 설정 변경 또는 필요한 결정부터 보여줍니다. 대화 라우팅이 켜져 있으면 새 대화 필요 여부도 명시합니다.
3. 기본 `ask`는 변경 전이나 중요한 장애가 있을 때 확인합니다. 유지 또는 진행을 막지 않는 불확실성은 승인된 작업을 중단하지 않습니다. 계획 요청은 구현 승인이 아닙니다.

짧은 질문이나 바뀌지 않은 단계는 다시 라우팅하지 않습니다. 대화와 모델은 독립적으로 판단하며, 새 대화와 모델 변경이 함께 필요할 수도 있습니다.

## 설치

### Gemini CLI

```bash
gemini extensions install https://github.com/zyzdev/adaptive-task-routing-gemini --ref v0.5.0
```

설치 후 Gemini CLI를 다시 시작하세요.

### Claude Code

공개 디렉터리 신청은 심사 중입니다. 정식 등록 전에는 전용 저장소를 복제하고 플러그인 디렉터리를 지정해 Claude Code를 시작할 수 있습니다.

```bash
git clone --branch v0.5.0 https://github.com/zyzdev/adaptive-task-routing-claude.git
claude --plugin-dir "$PWD/adaptive-task-routing-claude"
```

### ChatGPT 및 Codex

[v0.5.0 Release](https://github.com/zyzdev/adaptive-task-routing/releases/tag/v0.5.0)에서 `adaptive-task-routing-openai-0.5.0.zip`을 다운로드하세요. 로컬 플러그인을 지원하는 화면에서는 압축을 푼 플러그인을 Plugin 또는 Marketplace 기능으로 추가합니다. 공개 디렉터리 제공 여부는 OpenAI 심사 결과에 따릅니다.

## 처음 사용하기

활성화한 뒤 새 대화에서 입력하세요:

> 이 프로젝트를 검토하고 개선 계획을 제안해 주세요. 아직 파일을 수정하지 마세요.

필요하면 adaptive-task-routing Skill 사용을 명시하세요. 계획 뒤에 안내가 나오며 구현은 시작하지 않습니다.

## 표시되는 내용

아래 예시는 서로 다른 상황이며 분석이나 계획 뒤에 표시됩니다. 유지 예시는 확인 작업이 승인되었다고 가정합니다. 계획만 요청했다면 계획 전달로 마칩니다. 모델과 기본 추론 옵션은 예시이며 플랫폼에 따라 다릅니다. 현재 AI 값은 실제로 관측된 값이어야 합니다.

**전환할 가치가 작을 때**

```text
---

### Adaptive Task Routing

✓ 현재 설정 유지

현재 설정으로 충분하며 남은 작업이 적어 전환의 이점이 제한적입니다.

대화: 현재 대화를 유지하므로 새 대화는 필요하지 않습니다.
현재 AI: GPT-5.6 Sol / high.

조작이 필요하지 않습니다. 승인된 확인 작업을 계속합니다.
```

**변경할 가치가 있을 때**

```text
---

### Adaptive Task Routing

AI 설정 변경

다음 단계의 검증 요구가 관측된 현재 설정의 역량을 넘어섭니다.

대화: 현재 대화를 유지하므로 새 대화는 필요하지 않습니다.
작업에 적합한 설정: GPT-6 Astra / high.

GPT-6 Astra / high 설정으로 바꿀까요?
```

조작 방법은 환경에 따라 다릅니다. `auto`도 검증한 뒤에만 변경 완료를 보고합니다. 정보가 부족하면 임시 유지와 이유를 표시하고 적합성을 단정하지 않습니다. 중요한 장애가 있으면 구체적인 질문을 합니다.

계획만 요청했다면 계획을 전달하고 구현은 시작하지 않았다고 설명합니다. 인계가 필요하면 새 대화 시작 확인과 함께 필요한 사실과 제약만 요약합니다.

## 모드와 표시 상세도

| 모드 | 동작 |
| --- | --- |
| `ask`(기본) | 변경 전이나 중요한 장애가 있을 때 확인합니다. 유지와 진행을 막지 않는 defer는 승인된 작업을 계속합니다. |
| `auto` | 타당하고 승인됐으며 실행과 검증이 가능한 변경만 적용합니다. 대체 동작을 설명하고 중요한 장애를 무시하지 않습니다. |
| `off` | 지정 Router와 해당 출력을 생략합니다. |

Context와 Model은 독립적입니다. “이번에는 대화 라우팅 off”, “모델 라우팅 ask”, “이 대화에서 둘 다 auto”라고 설정할 수 있습니다. 모드 변경 자체는 작업을 승인하지 않습니다.

기본 표시는 간결합니다. “자세히 설명해 주세요”라고 하면 **최소 필요 설정, 작업에 적합한 설정, 성능을 높일 가치**를 볼 수 있습니다. 적합한 설정과 지금 할 행동은 별개입니다. 상세 표시는 기존 평가를 재사용하며 전환 점수는 진단용으로 남깁니다. compact／detailed는 추가 모드가 아닙니다.

유지가 확인되면 간결한 표시에는 관측된 현재 AI만 보여주며 다른 적합 설정은 상세 설명에 남깁니다. 현재 AI를 알아도 전환 비용이나 이점이 불확실하면 임시 유지로 표시할 수 있습니다.

## 추천의 판단 기준

- **대화 환경:** 다음 작업에 필요한 정보와 이전 작업의 가정이나 제약이 새 작업에 간섭할 가능성을 평가합니다. 이를 바탕으로 현재 대화 유지, 필요한 정보 요약 후 전달, 새 대화 시작 중 적합한 방법을 추천합니다.
- **모델과 추론 강도:** 작업 난이도, 모호함, 오류 비용과 검증 필요성을 고려하여 최소 충분 설정과 권장 설정을 제시하고, 상향 조정의 가치를 설명합니다.
- **모델 정보 출처:** 현재 환경에서 얻을 수 있는 정보를 우선 사용합니다. 얻을 수 없다면 플랫폼에 맞는 유효한 내장 참고 자료를 사용합니다. 참고 자료에 있는 모델이라도 사용자의 계정에서 선택할 수 있다는 뜻은 아닙니다.

자세한 판단 원칙과 플랫폼 제약은 [설계 및 아키텍처(영어)](../architecture.md)를 참고하세요.

## 명시적으로 실행하기

- Skill 멘션을 지원하는 Codex: `$adaptive-task-routing`
- Claude Code: `/adaptive-task-routing:adaptive-task-routing`
- 기타 화면: “이 작업을 시작하기 전에 adaptive-task-routing Skill을 사용해 주세요.”라고 요청합니다.

## 제거

Gemini CLI:

```bash
gemini extensions uninstall adaptive-task-routing
```

Claude Code를 `--plugin-dir`로 시작했다면 세션을 종료하고 복제한 디렉터리를 삭제하면 됩니다. ChatGPT 또는 Codex에서는 설치할 때 사용한 Plugin 또는 Marketplace 화면에서 비활성화하거나 제거하세요.

## 문제 해결

- 설치 또는 업데이트 후 새 대화를 시작하세요.
- Skill 목록에 `adaptive-task-routing`, `task-context-router`, `research-model-router`가 있는지 확인하세요.
- 추천이 나타나지 않으면 Skill을 한 번 명시적으로 실행해 보세요.
- 추천이 표시되었다고 해서 모델이나 대화가 전환된 것은 아닙니다. 검증된 자동 변경만 적용 완료로 보고됩니다.

개발 및 검증에 관한 자세한 내용은 [개발 안내(영어)](https://github.com/zyzdev/adaptive-task-routing/blob/main/DEVELOPMENT.md)를 참고하세요.
