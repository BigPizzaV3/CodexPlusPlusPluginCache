# 完整路由範例

以下是設計範例，不是模型實測結果。模型名稱都是虛構測試標籤，不是可選產品型號。
所有 Routing 訊息都接在使用者要求的分析或可操作計畫後面；未特別指定時，兩個 Router 都使用 ask。

## 只要求計畫時保留設定

使用者要求檢查啟動速度並提出改善計畫，沒有授權實作。已觀察的 fixture-balanced / medium
有可靠的設定及驗證依據，足以執行計畫提出的後續核對；若之後授權執行，預估工作短，切換收益不足。

```text
檢查發現啟動程序將可獨立的讀取依序執行。改善計畫：
1. 延後非必要服務。
2. 平行讀取獨立資料。
3. 以啟動順序及耗時測試確認改善。

---

### Adaptive Task Routing

✓ 維持目前設定

若後續授權執行計畫中的核對，目前設定已有足夠驗證依據，預期切換改善有限。

對話：留在目前對話，不需開新對話。
目前 AI：fixture-balanced / medium。

分析與計畫已交付；尚未開始實作。
```

不必再問「要不要保持目前設定」，也不能自行實作。若使用者已要求執行，結尾改成
說明並執行下一個已授權步驟。計畫交付完成不是路由阻礙。

## 資訊不足但可繼續

清單支援 fixture-balanced / high，但目前模型無法確認。使用者已授權有界、可驗證的
檢查，而且沒有重大品質阻礙。即使目前設定已知，切換成本或效益不明也可暫時沿用。

```text
計畫：比對版本來源，檢查發布產物，最後執行對應測試。

---

### Adaptive Task Routing

暫時沿用設定

切換效益尚未確立，先沿用設定完成可驗證的檢查。

對話：留在目前對話，不需開新對話。
任務適配設定：fixture-balanced / high，不代表現在需要切換。

接著執行已授權的檢查。
```

若先前驗證失敗，導致無法負責任地決定下一步，就改用「? 需要你的決定」，指出缺少的
具體選擇並詢問。只有模型 metadata 未知不構成這種阻礙，也不能冒稱目前模型已確認適合。

## 調整設定與同時交接

已觀察設定無法達到下一階段品質要求，且另一組受支援設定有足夠切換收益。ask 在變更前詢問：

```text
計畫：比對版本來源，檢查發布產物，最後執行對應測試。

---

### Adaptive Task Routing

↑ 建議調整 AI 設定

目前已觀察設定未能可靠完成下一階段所需的驗證。

對話：留在目前對話，不需開新對話。
任務適配設定：fixture-balanced / high。

要改用 fixture-balanced / high 嗎？
```

若同時需要新對話，主動作改成「→ 建議交接」，顯示「對話：建議開新對話並交接必要脈絡，待你確認」。
只帶入目標、已確認發現、API 限制、相關檔案與下一步。目的地選項已知才顯示下一階段模型，
否則明確延後。模型保留不能代替對話決定；全新開始則不帶舊任務交接。

`auto` 仍須切換值得、已授權、可操作且可驗證。沒有控制時說明實際處理方式，不能說
正在套用；只有沒有重大品質或目的地阻礙時才繼續已授權工作。使用者已接受目標後不重複詢問。

## 詳細說明與關閉元件

要求詳細說明時重用同一 Gate，增加最低足夠設定、任務適配設定與升級理由。內部
recommended_setting 名稱不變。切換評分與來源診斷不是一般詳細輸出。
Context-off 省略整個對話評估；Model-off 省略模型建議與控制；兩者都 off 則不輸出路由。
compact／detailed 是顯示偏好，不是新模式。

## Gemini 的未知模型範例

以下是假設模型身分無法確認、只知道原生 Reasoning 採模型預設的設計範例。
模型預設不能代替目前模型身分；完成本輪分析也不能證明後續實作的品質需求已滿足。

```text
檢查發現版本定義分散，測試未核對發布產物。改善計畫：
1. 統一版本來源。
2. 加入產物版本比對。
3. 補上發布失敗情境的測試。

---

### Adaptive Task Routing

暫時沿用設定

目前模型身分無法可靠確認，後續階段的切換效益尚未確立；本輪僅交付分析與計畫。

對話：留在目前對話，不需開新對話。

分析與計畫已交付；尚未開始實作。
```
