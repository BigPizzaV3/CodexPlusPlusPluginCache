# OneNote

- For requests to export, back up, archive, download, or migrate OneNote content to Markdown or Obsidian, use [Export OneNote to Markdown](../export-onenote-to-markdown/SKILL.md). The live `export_page_as_markdown` action exports one personal page at a time as a downloadable Markdown file; do not promise a ZIP, direct Obsidian-vault write, embedded resources, or shared-page export.
- Start with the narrowest discovery path. Use `list_notebooks`, then `list_sections` and `list_section_groups` for a named personal notebook; use `list_pages` for a known section or a bounded recent-page window. Match returned IDs, titles, parent metadata, and web URLs rather than guessing opaque IDs from a browser URL.
- Use `search_pages_by_title` only for case-insensitive title matching. For a body-content request, use `search_pages_by_text` with the narrowest known section and date window, then continue with `next_skip` only when broader coverage is needed. It scans at most ten owner-verified personal pages per call, searches sanitized visible text rather than raw HTML, and is not a global native index; say when pagination or truncation leaves the search incomplete.
- Prefer `get_page_text` for visible paragraph-like text, checklist tags, and addressable blocks; use `get_page_tables` for table structure, `find_page_text` for one exact case-sensitive occurrence in one known page, and `fetch_page` when the original bounded HTML is needed. Use `fetch_page_resource` only with both the page ID and exact resource ID observed in that page's current content.
- Raw `fetch_page` HTML can contain non-visible provider markup; do not surface it or choose it as an update target, and rely on visible structured extractors for user-visible content.
- Personal-only discovery, read, export, hierarchy, and update actions operate only on notebooks owned by the signed-in Microsoft account; they intentionally omit directly shared personal notebooks. Treat the mixed `create_page` and `copy_page_to_section` actions as shared-capable. For a Microsoft 365 group or SharePoint site notebook, require a known `resource_type` and `resource_id`, then use `list_shared_notebooks`, `list_shared_sections`, `list_shared_section_groups`, `list_shared_pages`, and `fetch_shared_page`. Do not pass shared-page IDs to personal-only page actions or imply a shared structured extractor that is not present in the live tool surface.
- Before a targeted edit, read a fresh snapshot with element IDs or structured update targets. Use `update_page` or `update_shared_page` for exact insert, replace, prepend, or append operations, and re-read after any mutation because targets can become stale.
- Use `append_to_page` or `append_to_shared_page` for simple additive notes. Use `add_page_resources` on a personal page for staged images, PDF printouts, or attachments, and keep the supplied filenames and MIME types accurate.
- Use `create_notebook`, `create_section_group`, and `create_section` only in the destination the user selected; `create_page` can target a personal section or a known shared section. Use simple OneNote-compatible HTML for new content, and disambiguate similarly named notebooks, sections, or pages before writing.
- Treat page copying as asynchronous: call `copy_page_to_section`, retain its returned operation reference, and poll `get_operation` until it reaches a terminal state. Never report the copy as complete from the initial accepted response.
- Use `next_skip` for bounded pagination; never invoke or reconstruct an opaque `next_link` URL.
- Read-only requests do not authorize edits. Confirm the exact target and intended change before a consequential write, and require explicit confirmation immediately before `delete_page` because deletion is permanent.
