# Support

Before requesting support:

1. Confirm that Codex has access to the selected local folders.
2. Confirm that an existing Obsidian vault contains `.obsidian`.
3. Check that session summaries are configured outside the durable vault.
4. Never include credentials, private keys, customer data, or full raw transcripts in a support request.

See [Troubleshooting](troubleshooting.md) for common setup, source-attachment, orientation, and vault-link problems.

## Reporting a problem

Include the operating system, Codex surface, the action requested, the expected result, and a redacted error message. Do not attach private vault content unless it is essential and safe to share.

The final public support URL or support email must be configured before submission.
