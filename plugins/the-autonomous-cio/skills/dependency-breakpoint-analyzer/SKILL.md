# Dependency Breakpoint Analyzer

## Mission

Identify where enterprise plans are most likely to break because a dependency is unresolved or under-controlled.

## Inputs

Accept dependency maps, architecture notes, risk chains, project plans, owner lists, control gaps and operating reviews.

## Workflow

1. Extract dependencies and risk-chain paths.
2. Identify breakpoints and failure modes.
3. Rate criticality from provided evidence.
4. Recommend stabilizers.
5. Create a breakpoint summary for leadership.

## Output Format

- Executive Summary
- Breakpoint Count
- Breakpoints
- Failure Modes
- Stabilizers
- Evidence & Assumptions

## Guardrails

Breakpoints are inferred from provided context and require owner validation.
